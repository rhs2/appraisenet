# AWS deployment

Target architecture (all resources in `terraform/`):

```
GitHub Actions (deploy.yml)
   build image -> push to ECR -> `aws ecs update-service --force-new-deployment`

Internet -> ALB (80/443) -> ECS Fargate service (autoscaled 1..4 tasks)
                               task = [api container (gunicorn, port 5000),
                                       mlflow sidecar (port 5001, Postgres backend, S3 artifacts)]
                               secrets from SSM Parameter Store (SecureString)
                          -> RDS PostgreSQL 16 (predictions, drift reports, MLflow runs)
                          -> S3 bucket (MLflow artifacts, model bundles), versioned + encrypted
EventBridge (daily) -> one-off Fargate task: `appraisenet monitor --from-db --store`
CloudWatch Logs + Container Insights
```

## One-time setup

```bash
cd deploy/aws/terraform
cp example.tfvars prod.tfvars        # fill in VPC, subnets, certificate (git-ignored)
terraform init
terraform apply -var-file=prod.tfvars
```

Outputs give the ECR repository URL, the cluster and service names, the
artifacts bucket and the ALB URL. The database password is generated by
Terraform and stored only in SSM (`/appraisenet-prod/DATABASE_URL`);
the containers receive it as an ECS secret, never as a plain environment
variable in any file.

## Shipping a model

The image bakes whatever is in `models/` at build time. The intended flow:

1. `make benchmark` on a training machine (or a CI job with the data volume).
2. `git commit` the model cards and figures; upload `models/<dataset>/best.joblib`
   to `s3://<artifacts-bucket>/models/<git-sha>/` (the joblib files are
   git-ignored on purpose).
3. Tag a release: `git tag v1.0.0 && git push --tags`. The deploy workflow
   pulls the matching model bundle from S3 into `models/`, builds and pushes
   the image and rolls the ECS service with the circuit breaker enabled
   (automatic rollback on failed health checks).

## GitHub Actions secrets

| secret | used for |
|--------|----------|
| `AWS_ROLE_TO_ASSUME` | OIDC role with ECR push, ECS update and S3 read on the artifacts bucket |
| `AWS_REGION` | region of the stack |
| `ECR_REPOSITORY`, `ECS_CLUSTER`, `ECS_SERVICE`, `ARTIFACTS_BUCKET` | Terraform outputs |

No long-lived AWS keys are stored: the workflow uses OpenID Connect.

## Operations

- Logs: CloudWatch group `/ecs/appraisenet-<env>`, streams `api/*` and `mlflow/*`.
- Health: ALB target health on `/health`; the container has its own health check.
- Drift: the daily EventBridge task writes a report per deployed dataset into
  the `drift_reports` table; `GET /api/stats` shows the latest status.
- Scaling: CPU target tracking at 60 percent, 1 to 4 tasks; change
  `desired_count` / `max_count` in `prod.tfvars`.
- Database: `multi_az`, 7-day backups and deletion protection are enabled
  when `environment = "prod"`.

## Cost notes

Smallest useful footprint (1 Fargate task at 1 vCPU / 2 GB, db.t4g.micro,
ALB, S3) is in the tens of dollars per month. Scale the task size before the
task count: the CNN and BiLSTM models run comfortably on CPU at this size.
